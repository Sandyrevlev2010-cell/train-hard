# Train Hard — анализ существующего кода перед MVP-реработкой

> Исторический документ первой итерации. В security-итерации режим `trust` и
> демо-активация удалены — актуальное состояние см. в `SECURITY-AUDIT.md` и
> `PREMIUM-PAYMENTS.md`.

Исходник: `TrainHard-app-premium-animated.html` — монолитный самодостаточный HTML (~4 МБ):
инлайн Tailwind v4, стили «STOIC», шрифты и картинки в base64, минифицированный React-бандл
(~2,6 МБ, React 19), плюс несколько vanilla-скриптов (эффекты, Arena, база знаний, мобильная
оптимизация, premium-анимации). Своего backend-репозитория в исходнике нет — есть **клиент,
обращающийся к внешнему API** (`/api/...`, по умолчанию `https://api.trainhard.ru/api`).

## 2. Что требует backend (и что с этим делать)

| Функция | Где | Решение для MVP |
|---|---|---|
| Регистрация/вход на сервере (`/api/register`, `/api/login`) | React-бандл | **Убрать**: вход не нужен, гостевой режим |
| Синхронизация состояния (`/api/state`), `/api/me`, `/api/ping`, `/api/logout`, Bearer-токен | React-бандл | **Отключить**: API-клиент заменён офлайн-заглушкой (0 сетевых вызовов) |
| Блок «Сервер и синхронизация» в профиле (URL API, статус) | React-бандл | **Удалить из UI** |
| «Выйти из аккаунта» | профиль | **Удалить** (останется «Сбросить всё») |
| ARENA: группы по коду, заявки, рейтинги, подиум | отдельный скрипт + CSS + карточка на главной | **Удалить полностью** — имитирует мультиплеер, которого нет; создаёт ложное впечатление соцфункции |
| Карточка «Рейтинг · Арена» на главной | React-бандл | **Заменить** карточкой Premium (по спеку CTA на главной) |
| Кнопка оплаты Premium | `payPremium()` = тост «Платёжный модуль пока не подключён» | **Заменить** на PremiumManager + платёжный адаптер |
| Текст «За что я плачу?» («обслуживание нейросети…») | модалка | **Переписать честно** (серверов и нейросети в MVP нет) |
| Тост «Ошибка синхронизации с сервером» | авто-сохранение | Уходит вместе с API-клиентом (заглушка не «ошибается») |
| Cloudflare-скрипты (2 шт., `/cdn-cgi/...`) | хвост файла | **Мусор от экспорта** — удалить |

## 3. Что переводим на localStorage / IndexedDB

Всё состояние уже в localStorage — ключи сохранены как есть (обратная совместимость
с установленными у пользователей копиями):

- `trainhard_react_session` — сессия (теперь всегда `guest` для новых);
- `trainhard_react_data_<login>` — прогресс, история, streak, настройки;
- `trainhard_react_accounts` — устарел (не читается новым флоу, не удаляем — данные не теряем);
- `trainhard_api` — URL API (больше не используется, оставлен без чтения);
- НОВОЕ: `trainhard_premium_v1` (entitlement), `trainhard_interval_timer_v1` (настройки таймера),
  `trainhard_analytics_v1` (локальные счётчики событий).

Объёмы данных маленькие (килобайты), IndexedDB не требуется. Доступ к хранилищу вынесен в
`StorageService` (модуль `src/storage/storage-service.js`) — единая точка замены на API в будущем.
Если localStorage недоступен (приватный режим, sandbox) — модуль работает в memory-режиме,
приложение не падает.

## 4. Что удаляем

- ARENA целиком: скрипт, CSS, плавающая кнопка, карточка на главной, финальный HTML-комментарий;
- 2 Cloudflare-скрипта;
- экран логина/регистрации в онбординге (шаг 0) — онбординг начинается с выбора цели;
- кнопка «Выйти из аккаунта», блок «Сервер и синхронизация»;
- упоминания «демо-режим», «демо-версия», «аккаунт» в UI.

## 5. Что переделываем

- **Boot**: без сессии → создаётся локальный профиль `guest`, онбординг с шага «цель» (3 шага вместо 4);
- **API-клиент** `we()` → офлайн-заглушка `return null` (единая точка, 0 запросов);
- **Профиль**: без аккаунт-логики; подпись «данные хранятся только на этом устройстве»;
- **Экран Premium** (`pay`-модалка): переписан целиком — преимущества, состав Free/Premium,
  цена/период, покупка, восстановление, условия (см. `docs/PREMIUM-PAYMENTS.md`);
- **Онбординг**: прогресс-бар на 3 шага;
- Чип статуса в шапке: `guest` → «Спортсмен» (до ввода имени).

## 6. Что добавляем для Premium

- **PremiumManager** (`src/premium/premium-manager.js`): централизованная проверка
  `isPremium()/until()/daysLeft()`, активация/окончание, подписка на изменения, рендер Premium-экрана.
  Все проверки Premium в React-коде уже шли через одно место (`isPrem` из контекста ≤ `premiumUntil`),
  теперь entitlement живёт в одном ключе и прокидывается в состояние через `window.__THPatch({premiumUntil})`
  — единственная точка интеграции, десятков разбросанных проверок нет и не было.
- **PaymentAdapter** (`src/premium/payment-adapter.js`): ЮKassa/ЮMoney Quickpay — переход на
  защищённую страницу провайдера, карта в приложение не попадает. Возврат с меткой `label`,
  режимы активации `trust`/`verify` (см. док). Пока касса не подключена — покупка честно
  помечена как «подключается», нерабочей кнопки «Купить» нет.
- Гейтинг Premium-контента сохранён: Питание (КБЖУ), программы Old School (Арнольд/Ронни/Кевин), AI-сплит.
- Демо-активация для E2E-проверки гейтинга: открывать приложение с `?th_demo=1`.

## 7. Что потребуется для Android / RuStore

- Обёртка **Capacitor** (WebView + тот же `app/index.html` как `www/`): весь функционал
  (тренировки, таймеры, прогресс, Premium-гейтинг) уже работает локально в WebView — это не
  «оболочка, открывающая сайт»;
- Платежи в RuStore-сборке: **RuStore Billing SDK** через плагин Capacitor (замена PaymentAdapter
  в одном модуле — интерфейс адаптера совпадает);
- Иконки/манифест уже готовы (`app/icons`, `app/manifest.webmanifest`), splash — тема RuStore;
- Подробная пошаговая инструкция: `docs/ANDROID-RUSTORE.md`.
