# Train Hard Challenges — локальная система челленджей (без backend)

## Принцип

**CHALLENGE DATA IS SELF-CONTAINED INSIDE THE URL.** Все параметры челленджа
кодируются в ссылку (`?challenge=<payload>`); сервер не участвует ни на одном
шаге: ни создание, ни хранение, ни прогресс. Мотивация передаётся **speechId**
(`s1`…`s6`), а не текстом; силовая цель — коротким id упражнения (`bp|sq|dl`) +
вес в кг.

```
Пользователь A: Create → Encode → URL → Share/Copy/QR
Пользователь B: Open URL → Decode → Preview → Join → локальная копия → Train
```

инкапсулирован в `loadAll/persist`, UI не меняется). Сейчас — LocalChallengeProvider only.

## Кнопка «Челленджи» и новый флоу создания

- **FAB ⚡ «Челленджи»** — правый нижний угол главной, зеркало кнопки огонька
  (левый нижний угол); стоит **над нижней панелью навигации** (отступ = высота
  панели + 12px + safe-area), появляется только на главной, красная точка при
  активных челленджах. Скрывается при **любом** оверлее приложения: боковое меню
  (`z-50`), модалки (`z-40`), оверлей челленджей — и возвращается после закрытия.
  Реакция мгновенная (MutationObserver) + интервальная страховка;
- Шаг 1 — **«Для кого?»**: `ДЛЯ СЕБЯ` (челлендж сразу присоединяется, без шаринга)
  или `ДЛЯ ДРУГА` (создание заканчивается ссылкой/QR);
- Шаг 2 — только **2 кнопки типа**: `ТРЕНИРОВКИ` и `СИЛА` (шаблоны убраны);
- Редактор тренировок — ТОЛЬКО один ряд пресетов **«N тренировок подряд»: 3 / 7 / 14 / 30**
  (все — бесплатный уровень) + поле **«или своё» (2–30)**; окно подбирается автоматически
  (7/14/30/60 дней). Фокус и сложность убраны из редактора (в данных остаются по
  умолчанию fullbody/standard — формат ссылки не менялся);
- Сила: срок 3/7/14/30 дней (все бесплатные) или **свой срок 1–90 дней**;
- **СКАНИРОВАТЬ QR 📷** — кнопка в списке челленджей: камера сканирует QR-код челленджа
  и открывает превью. Декодер локальный (vendored jsQR, MIT; API BarcodeDetector не
  требуется), картинка не покидает устройство; в окружениях без камеры — ручная вставка
  ссылки `?challenge=…` (принимается и «сырой» payload).
  Конвейер верифицирован тестом P4–P6 (node-canvas): getUserMedia → видео-кадр →
  jsQR → превью, поток останавливается после декодирования. Камера работает на
  HTTPS-хостинге и в Android-сборке; в sandbox-предпросмотре (iframe без
  camera-разрешения) и при file:// браузер не даёт камеру — экран честно
  предлагает ручную вставку ссылки (кнопка камеры не «фальшивая»: она
  feature-detectится и деградирует с явным объяснением).

### Исправления UI-итерации (кнопка/карточка/длительность)

- **FAB пропадал после первого открытия челленджей**: класс `thch-open` вешался
  на body навсегда и скрывал кнопку. Теперь класс ставится при открытии оверлея
  и снимается при закрытии — кнопка «Челленджи» всегда возвращается на главную;
- Карточка «Челленджи» в разделе «Прогресс» открывается кликом **по любому её
  месту** (раньше — только по строке челленджа);
- Длительности 14 и 30 дней разблокированы в бесплатном уровне (тренировочные
  пресеты и силовые сроки);
- Произвольная длительность: «подряд» 2–30 (окно авто), силовой срок 1–90 дней;
  кодек валидирует диапазоны вместо списка значений (2≤n≤30, 1≤d≤90, целые);
- Ввод своих значений не перерисовывает экран: число сохраняется в черновик,
  подтверждение — строкой «Принято: …» под полем; кнопка ДАЛЕЕ срабатывает
  с первого клика (раньше пересоздание экрана «съедало» ввод).

### Исправленные баги этой итерации

- **«Выбрал 7 подряд — в Прогрессе 0/4»**: `sanitizeStored` при каждом чтении из
  localStorage проверял цель по старому списку [3,4,5,10] и молча превращал 7/14/30 в 4.
  Исправлено: валидация по `Codec.TARGETS` (тесты S4/S4c);
- «Для себя» при исчерпании лимита активных челленджей тихо переходил к экрану шаринга —
  теперь показывает явное предупреждение «Не удалось присоединиться: лимит…» (S5b);
- В «Прогрессе» остаток дней показывался только при ≤3 днях — теперь у всех активных
  («0 / 7 подряд · 14 дн»), чтобы челленджи не путались (S4c–S4e);
- FAB «Челленджи» больше не перекрывает открытый оверлей челленджей (body.thch-open).

### Семантика «подряд»

Перерыв между тренировками — **максимум 1 день**. Если прошло 2+ дня
(как у серии огонька), счёт челленджа начинается заново (notice в карточке),
челлендж остаётся активным до завершения окна d.

## Формат payload

Обычный (workout):
```json
{"v":1,"id":"TH7K92","t":"7 Day Challenge","d":7,"n":4,"f":"fullbody","l":"standard","s":"s1"}
```
Силовой (strength):
```json
{"v":1,"id":"TH8K2","t":"Strength","d":30,"f":"strength","e":"bp","w":80,"s":"s3"}
```
Схема: `v` версия · `id` TH+4–8 символов · `t` название ≤40 · `d` дни (3/7/14/30/60) ·
`n` цель тренировок (3/4/5/7/10/14/30) · `f` фокус (7 значений) · `l` сложность ·
`e` упражнение (bp/sq/dl) · `w` кг (1–500, шаг 0.5) · `s` speechId.
Транспорт: JSON → UTF-8 → **Base64URL**. Лимит payload — 600 символов.

Base64 — транспорт, не шифрование: в payload нет паролей, токенов, платёжных
данных, имён и персональных данных; QR содержит ту же ссылку (не «голый» id).

## Ключевые решения

| Тема | Решение |
|---|---|
| Старт челленджа | `startMode=onJoin`: `joinedAt` фиксируется у каждого участника свой |
| Дубликат join | отклоняется: «Уже участвуешь» + [Открыть челлендж] |
| Лимиты | FREE — 3 активных, Premium — 10 (присоединиться к чужому можно всегда — вирусность не блокируется) |
| Free/Premium | Free: создание, любые сроки и цели (вкл. 14/30 дней и свои значения), речи s1–s3, share/QR/join/прогресс/сканер. Premium: речи s4–s6, лимит 10 активных |
| Прогресс тренировок | автоматический: обёртка `completeWorkout` вызывает `__THChallenges.onWorkoutCompleted(day,dateStr)`; дедуп по дате |
| Силовой прогресс | вручную (личный журнал) + автоподтягивание из СУЩЕСТВУЮЩИХ рекордов: обёртка `addRecord` → `onRecordAdded(exercise,kg)`; стартовое значение — лучший рекорд |
| Завершение | workout: `completed ≥ target`; strength: `current ≥ target` (точное равенство не требуется) |
| Дни остатка | `joinedAt + durationDays`; время устройства локальное (accepted limitation) |
| Мотивация | 6 речей (id, title, short, full, completion); в челлендже только `speechId`; unknown → fallback s1 + пометка «Мотивация по умолчанию» |
| Safety | «личная цель, не соревнование», без «через боль любой ценой», без медицинских обещаний, без сравнения с другими людьми |
| Фейковые друзья | никакого «Alex completed 3/4», участников и лидербордов — без backend это неизвестно |

## Интеграция в раздел «Прогресс»

- Карточка **«Челленджи»** (перед «Достижениями»): шкала прогресса каждого
  челленджа (своего и присоединённого), `X / N подряд` или `кг`, `%`-заполнение,
  «ГОТОВО» у завершённых; клик открывает челленджи;
- **Достижения — серые** (grayscale), пока уровень не достигнут; как только
  достижение получено (например, «7 дней серии») — иконка становится цветной;
- **Сброс серии**: если пользователь не тренировался 2 дня, серия огонька
  обнуляется уже при загрузке профиля (патч P25, то же правило, что у `ge()`
  в бандле) и показывается уведомление «Серия обновилась: вы не тренировались 2 дня».

## Обработка ошибок (§76)

| Ситуация | Экран |
|---|---|
| Мусорный base64/JSON/структура | НЕКОРРЕКТНАЯ ССЫЛКА |
| payload > 600 символов | НЕКОРРЕКТНЫЙ ЧЕЛЛЕНДЖ (слишком большая) |
| версия ≠ 1 | ВЕРСИЯ НЕ ПОДДЕРЖИВАЕТСЯ |
| неизвестное упражнение | СИЛОВАЯ ЦЕЛЬ НЕ ПОДДЕРЖИВАЕТСЯ |
| неизвестная речь | DEFAULT MOTIVATION (fallback s1) |
| неизвестные workoutIds | «Некоторые тренировки недоступны в этой версии» |

Приложение не падает ни в одном случае (покрыто тестами T26–T30).

## Безопасность

- Все данные URL недоверены: валидация полей/значений/длин в кодеке; title
  выводится только через `textContent` (XSS-тест с `<img onerror>` — зелёный);
- URL очищается `history.replaceState` сразу после чтения;
- 0 сетевых запросов во всём флоу (офлайн-тест T31), QR генерируется локально;
- секретов нет; платёжных данных нет; Premium челленджами не активируется;
- «Сбросить всё» в приложении очищает и челленджи (патч P24).

## Аналитика (локальная, whitelist)

`challenge_created` · `challenge_shared` · `challenge_joined` · `challenge_completed` —
только счётчики, без identities и текстов.

## Интеграция в приложение

- Пункт меню «Челленджи» (боковое меню, патч P16a);
- Хуки в бандле: P21 (завершение тренировки) и P23 (новая проходка);
- P24 — очистка challenge-ключей при сбросе данных;
- Все экраны (список/создание/шаринг/QR/превью/детали/финал) — vanilla-оверлей
  `.thch` в фирменном монохроме; дизайн и навигация приложения не менялись.
