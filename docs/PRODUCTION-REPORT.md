## Исправлено

- **BUG-001, BUG-002, BUG-003 — полностью** (архив воспроизводим: распаковка →
  npm install → npm test → 301 ✔ → build OK; guard сборки; честные цифры в доках).
- **BUG-004/006/007 — серверная половина готова и покрыта тестами** (57 тестов
  бэкенда): auth по подписанному initData, CRUD тренировок/подходов,
  идемпотентность POST, PR/Total из истории с пересчётом, группы/подгруппы/
  инвайты, серверный лидерборд (значение ↓ → раньше достигший ↑ → одинаковое
  место), соревнования с окнами зачёта, программы с раскладкой %1ПМ (шаг
  1.25/2.5/5), синхронизация очереди офлайн-операций, серверная верификация TON.
- **BUG-005** — задокументирован как осознанный офлайн-дизайн, без фейков.

## Осталось (честно)

1. **Переключение фронтенда на API** — главная незакрытая работа: бандл (4 МБ,
   минифицирован) по-прежнему работает на localStorage как основном хранилище;
   нужно подключить `/auth/telegram` + Bearer, `/sync` (очередь уже
   спроектирована), серверные лидерборды, `GET /premium` вместо локальной
   выдачи, `verifyUrl` для платежей. Это отдельная итерация минимальных патчей
   бандла — до её завершения High-уязвимости 004/006/007 не закрыты целиком.
2. **PgStore не прогонялся против живого PostgreSQL** (в окружении нет БД):
   SQL параметризован, схема в `db/migrations/001_init_up.sql`, контракт тот же, но
   интеграционный прогон обязателен до продакшена.
3. **`server/` — plain JavaScript, не TypeScript** — сознательное отклонение от
   «нового бэкенда на TS»: сохранена стратегия минимальных изменений стека.
4. Развёртывание: только за HTTPS-прокси с security-заголовками
   (`docs/SECURITY-HEADERS.md`); `BOT_TOKEN` — только в `.env` сервера.
5. Ограничение toncenter без API-ключа (1 rps) — при росте добавить ключ.
